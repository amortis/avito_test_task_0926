# avito_test_task_0926 — классификация ботов

Задача: по логу действий куки за сутки (окно наблюдения) оценить вероятность того, что это бот.
Метрика — **Precision при Recall ≥ 0.70** (`metric.py`, официальная реализация). Тест лежит
позже трейна по времени.

**Итог:** смесь рангов `HistGradientBoostingClassifier` + `ExtraTreesClassifier` на 61 признаке.
P@R0.7 на временной валидации — **0.83–0.87** (константа даёт ≈ 0.08).

### Баланс классов

Ботов в train **899 из 11 091 — 8.1%**. По дням доля стабильна: от 6.3% до 9.3%, явного
тренда нет.

Как это учтено:
- метрика ранжирующая (важен только порядок кук), поэтому порог и калибровка вероятностей не нужны;
- валидация по времени сохраняет естественную долю ботов, без стратификации и ресемплинга;
- `class_weight='balanced'` входил в перебор гиперпараметров и улучшения не дал;
  из-за малого числа ботов (на срезе 17.04 их всего 160) шум метрики около ±0.04 —
  все решения проверялись на нескольких временных срезах.

## 3. Модель

Смесь рангов 50/50:
- `HistGradientBoostingClassifier(max_iter=500, learning_rate=0.05, max_leaf_nodes=31,
  min_samples_leaf=20, l2_regularization=1.0, early_stopping=False)` с нативными категориальными
  признаками `device, ua_type, browser, os`;
- `ExtraTreesClassifier(n_estimators=500, min_samples_leaf=3, max_features=0.5)`, категории
  через one-hot, пропуски → −999.

Ранги, а не вероятности: у моделей разные шкалы, а метрике важен только порядок.
`early_stopping=False` задан явно: по умолчанию HGB включает раннюю остановку только при
n > 10 000, и финальная модель на 11 091 строке обучалась бы иначе, чем модели на валидации.

## 4. Валидация и результаты

Все схемы — по времени (обучение только на более ранних окнах).

| схема | HGB | смесь HGB + ET |
|---|---|---|
| train < 04-13, valid ≥ 04-13 (5161 кука, 408 ботов) | 0.841 | **0.867** |
| train < 04-17, valid ≥ 04-17 (1951 кука, 160 ботов) | 0.812 | **0.836** |
| rolling по дням 04-12..04-15 (tune) | 0.865 | **0.905** |
| rolling по дням 04-16..04-19 (hold) | 0.807 | **0.826** |

## 5. Что пробовал и что не сработало

| что | результат | решение |
|---|---|---|
| случайный перебор 60 конфигураций HGB (подбор на tune, проверка на hold) | лучшая по tune: 0.913 → на hold 0.798 (хуже исходной 0.816) | параметры не менялись: подбор переобучается под дни настройки |
| RandomForest / логистическая регрессия | hold 0.774 / 0.611 | не используются |
| признаки сессий (`n_sessions`, `event_entropy`, `share_dt_mult5`, …) | −0.01…−0.02 на всех схемах | убраны |
| `ua_n_cookies_max`, `burst_hour/min` | без них не хуже | убраны |
| объединение `desktop` и `web` | без изменений | не объединял |
| LightGBM, перебор 30 конфигураций (`compare_boosters.py`) | tune 0.923 → hold 0.807 | не используется: на hold не лучше HGB (0.816) |
| CatBoost, перебор 15 конфигураций | tune 0.902 → hold 0.790 | не используется |

Общий вывод по моделям: все три бустинга после подбора дают на tune 0.90–0.92, а на hold
0.79–0.81, то есть упираются в одно и то же качество, а выигрыш на tune — подгонка. Прирост дало не
усложнение модели, а смесь с ExtraTrees, которая ошибается иначе.

## 6. Ограничения

- Тест лежит позже всех валидационных окон, поведение ботов могло сдвинуться.
- `item_pop_*` использует события тестовых кук (без меток) — трансдуктивный признак; корректен,
  пока на инференсе доступен весь батч кук за период.
- При 160–400 ботах на валидации разницы меньше ~0.03 неотличимы от шума.
